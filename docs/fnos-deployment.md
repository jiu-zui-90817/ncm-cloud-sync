# 飞牛 NAS 部署指南

本项目提供**原生 fnOS 应用**：不依赖 Docker，安装后在应用中心启动，通过内置 Web UI 完成扫码登录、同步、设置和日志查看。文末保留 Docker 方式，供非 fnOS 环境或喜欢容器的用户使用。

## 一、原生应用（推荐）

### 1. 环境要求

- fnOS **1.2.0+**；
- x86_64 或 aarch64；
- 应用中心能安装官方 `python312` 依赖。

原生包已经内置 `httpx`、`pycryptodome`、`mutagen`、`PyYAML`、`qrcode`、`waitress` 的 cp312 离线依赖（x86_64 / aarch64 两套），运行时不需要 Docker、PyPI 或 NAS 上额外 `pip install`。

### 2. 获取 `.fpk`

从 [Releases](https://github.com/jiu-zui-90817/ncm-cloud-sync/releases) 下载最新的 `ncm-cloud-sync-<版本>.fpk`。

自行构建：

```bash
git clone https://github.com/jiu-zui-90817/ncm-cloud-sync.git
cd ncm-cloud-sync
# 需要官方 fnpack：放到 .tools/fnpack 或加入 PATH
bash scripts/build-fnos.sh
```

产物为 `dist/ncm-cloud-sync-<版本>.fpk`。构建机需要网络下载 wheel；NAS 运行时不需要。

### 3. 安装

1. 在飞牛 NAS 文件管理里上传 `.fpk`；
2. 打开应用中心 → 手动安装 → 选择文件；
3. 按向导填写音乐目录、同步间隔和日志级别；
4. 安装完成后启动应用。

安装向导字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 音乐目录 | `/vol1/1000/Music` | 必须是已存在的绝对路径；应用只读扫描 |
| 同步间隔 | `3600` | 秒，60–86400 |
| 日志级别 | `INFO` | DEBUG / INFO / WARNING / ERROR |

如果音乐目录对应用包用户不可读，请在应用中心授权目录，或在文件管理里给应用用户增加读取权限。应用不会修改音乐文件。

### 4. 从 0.2.x 迁移（仅旧版）

0.3.0 改了应用标识、包用户、数据目录和 Python 包名，应用中心不会把它当成 0.2.x 的升级。旧版本可以继续保留，确认新版本可用后再卸载。

1. 停止旧应用，备份 `/var/apps/wy-music-cloud/var`；
2. 安装新的 `ncm-cloud-sync-<版本>.fpk`，启动一次让新数据目录生成，然后停止；
3. 把旧目录里的 `settings.json` 和 `data/` 复制到 `/var/apps/ncm-cloud-sync/var/`，确认属主是新的应用用户 `ncm-cloud-sync`；
4. 启动新应用，检查账号、音乐目录、排除目录和通知配置；登录态失效时重新扫码；
5. 确认同步正常后再卸载旧应用，卸载前不要删除旧数据目录。

环境变量前缀也从 `WY_MUSIC_` 改为 `NCM_CLOUD_SYNC_`，Web 请求头改为 `X-NCM-Cloud-Sync`，Docker 服务名 / 容器名改为 `ncm-cloud-sync`；旧 `.env` 不会自动迁移。

### 5. 打开 Web UI

启动后点击桌面上的「NCM 云盘同步」图标，或应用中心的“打开”。页面通过飞牛统一网关加载，不需要开放端口，也不需要 SSH。右上角「关于」页可查看当前版本，并手动检查 GitHub 是否有新版本。

如果页面暂时打不开：

- 等 5–10 秒后刷新；
- 确认应用状态是“运行中”；
- 查看数据目录的 `app.log`，或在日志卡片点“诊断信息”。

### 6. 扫码登录

1. 点击「生成登录二维码」；
2. 打开网易云音乐手机 App 扫码；
3. 在手机上确认登录；
4. 页面显示昵称和云盘歌曲数后即可使用。

二维码约 4 分钟有效，过期后重新生成。登录态保存在 `data/session.json`，权限 0600。

扫码失败时，可以在登录卡片切换到 Cookie 登录：在电脑浏览器登录 [music.163.com](https://music.163.com)，从开发者工具复制包含 `MUSIC_U` 的 Cookie 粘贴保存。

### 7. 首次同步

推荐顺序：

1. 点「仅扫描」：只读扫描本地目录和云盘列表，列出本地待上传、已匹配、本地重复、云端独有，不写同步状态；
2. 看统计里的“待上传 / 跳过 / 失败”是否符合预期；
3. 确认后点「立即同步」：先做上传前接口预检，通过后才开始处理文件；
4. 后续交给后台按间隔自动执行。

同步过程中可以点「暂停」：当前文件处理完后停下，并暂停后台自动同步，点「继续」恢复；点「终止」尽快结束当前一轮，但不会关闭自动同步，下一轮仍按计划运行。两者都不会删除已上传记录，未处理文件下一轮继续。

「立即同步」会先检查登录态、云盘列表和上传查重接口；任何一项不可用都会中止本轮并推送失败通知，不会申请上传 token，也不会写文件状态。

「仅扫描」完成后，概览「待处理」显示最近一次仅扫描的待上传数量；之后再执行真实同步时，仍以数据库中的待处理状态为准。

### 8. 设置与日志

Web UI 设置项：

- **音乐目录**：一行一个绝对路径，可多个；
- **排除目录**：一行一个绝对路径，必须位于音乐目录内，整棵目录跳过；
- **自动同步**：关闭后只保留手动同步，后台调度不会自动触发；
- **同步间隔**：60–86400 秒；
- **请求间隔**：0–10 秒，网易云接口请求的最小间隔，默认 1 秒；遇到 405 限流时调大到 1.5～3 秒；
- **日志级别**：DEBUG / INFO / WARNING / ERROR；
- **通知**：在「通知」页添加渠道、启用 / 停用、发送测试，并按成功 / 失败 / 始终发送；成功通知默认只在有上传或补建文件时发送，空跑不推送，可勾选“空跑也通知”；支持 Telegram、Bark、ntfy、Gotify、Discord、Slack、钉钉机器人、Server酱、PushPlus、Pushover、PushDeer、Webhook、SMTP；
- **钉钉机器人安全设置**：支持加签（`secret`）和自定义关键词（`keyword`，多个用逗号分隔；消息不含关键词时程序会自动补第一个，不填时默认“网易云”）。IP 地址段白名单只能在钉钉机器人安全设置里填 NAS 的出口公网 IP，程序无法代填；同时启用加签、关键词和 IP 白名单时，三项都要满足。
- **云盘对账**：每轮开始读取云盘列表（`privateCloud.md5`），MD5 已在云盘的直接跳过；`needUpload=false` 的补建单独显示为“补建”，不计入上传数和字节数；
- **上传前预检**：每轮上传前检查登录态、云盘列表和上传查重接口，失败时中止本轮并推送失败通知；
- **云盘容量**：账号卡显示已用 / 总量 / 剩余和占用比例；每轮同步读取容量，上传前按剩余空间判断，空间不足的文件只标记失败并提示，不调用上传接口。

保存后对下一轮同步生效。日志卡片显示最近日志、每个日志文件的大小与总上限（`app.log` 单文件 2 MB、保留 2 个备份，总上限 6 MB）；进程 stdout/stderr 在 `app.out`。概览页显示最近 5 次有同步结果的执行记录，空跑和更早的记录会自动清理；点开任意一条可查看逐文件结果。概览的“已上传 / 待处理 / 本地缺失 / 跳过重复”统计卡也可以点开查看对应文件。通知失败只记日志，不会中断同步；`settings.json` 里的通知 token 为敏感信息，请勿分享。

### 9. 数据目录

原生应用的数据目录由 fnOS 的 `TRIM_PKGVAR` 提供，通常在：

```text
/var/apps/ncm-cloud-sync/var/
├── settings.json
├── app.log
├── app.out
├── app.pid
├── login.txt
└── data/
    ├── state.db
    ├── session.json
    ├── last_run.json
    └── qr.png
```

以应用中心显示的实际路径为准。

- `settings.json`：音乐目录、排除目录、自动同步、通知配置、同步间隔、请求间隔、日志级别；
- `data/state.db`：SQLite 同步状态，去重核心；
- `data/session.json`：登录态，敏感；
- `app.log`：Python 日志 handler 写入的运行日志，单文件 2 MB 自动轮转，保留 2 个备份；
- `app.out`：进程 stdout/stderr。

### 10. 升级

在应用中心用新 `.fpk` 覆盖安装即可。升级回调会保留设置、状态和登录态，只替换程序文件。升级前建议备份 `settings.json`、`data/state.db`、`data/session.json`。

从 0.3.0/0.3.1 升级到当前版本时，升级回调会把数据目录属主切到 `ncm-cloud-sync`。旧的 `wy-music-cloud` 系统用户不会自动删除，确认运行正常后可手动清理。若音乐目录提示无权限，在应用中心重新授权。

### 11. 备份与恢复

备份：

```bash
# 路径以应用中心显示为准
sudo tar czf ncm-cloud-sync-backup.tgz \
  -C /var/apps/ncm-cloud-sync/var \
  settings.json data/state.db data/session.json
```

恢复：停止应用，把文件放回对应位置，再启动。只恢复 `state.db` 也能工作；最坏情况下所有文件重新计算 MD5，云端查重仍会挡住重复上传。

### 12. 卸载

在应用中心卸载。卸载回调默认保留数据目录，方便重装后继续使用。若确定不再使用，可手动删除：

```bash
sudo rm -rf /var/apps/ncm-cloud-sync/var
```

删除前请确认路径；不同 fnOS 版本的目录可能不同。

### 13. 排错

**应用启动失败 / Web UI 502 或空白**

优先在页面日志卡片点“诊断信息”或“复制诊断”，那里会显示真实的 `app.log` 路径和内存日志。常见原因：官方 `python312` 依赖没有装好、CPU 架构不匹配、数据目录权限不对。确认应用状态是“运行中”，等几秒后刷新；仍失败则重新安装应用或安装依赖。

**没有日志文件 / 日志是空的**

服务端带内存日志缓冲。打开页面底部日志卡片，点“诊断信息”或“复制诊断”，会列出 `app.log` 路径、文件是否存在、数据目录、Python、PID、Socket 和最近 120 行日志；即使 `app.log` 因权限没写成，也能看到内存日志。反馈问题时复制整段诊断内容即可。

**扫码后手机提示“数据加载失败”或“服务器内部错误”**

先确认 NAS 时间准确，停止再启动应用，刷新页面后重新生成二维码。仍然失败时，展开登录卡片里的“查看诊断 / 日志”，点“复制诊断”获取版本和日志；同时可以改用 Cookie 登录。

**安装时提示“音乐目录不可用”**

- `目录不存在`：到文件管理里确认实际路径，注意 `Music` 等目录名大小写；
- `应用用户没有读取权限`：在应用中心给本应用授权该目录，或在文件管理里给应用用户 `ncm-cloud-sync` 增加读取权限；
- `必须是绝对路径`：路径要以 `/` 开头；
- 路径里不要带换行；从聊天或文件管理器粘贴时如果被拆成两行，删掉换行即可。

**扫描不到文件**

- 路径必须是绝对路径；
- 目录必须存在且应用用户可读；
- 检查扩展名是否在允许列表；
- 检查是否被 `exclude` 规则或“排除目录”命中。

**很多文件提示没有读取权限 / 失败里“无权限”很多**

应用以包用户 `ncm-cloud-sync` 运行。音乐文件属于其他用户且权限是 600 时无法读取。到「文件问题 → 权限体检」点「开始体检」，页面会列出无权限的文件 / 目录示例，并生成可在 fnOS 以 root 执行的 `setfacl` 修复命令（含默认 ACL）；体检只读，不会自动修改权限。也可以到应用中心给本应用授权音乐目录。授权后点“重置并重试”重新排队。

如果下载器强制使用 600 或 umask 077，默认 ACL 可能被覆盖；需要把下载器 umask 调整为 022/002，或在下载完成钩子里重新执行 `setfacl`。

**同步失败 / 上传时提示 [400] 参数错误**

日志会记录具体文件与错误阶段。常见原因是接口变动、Cookie 失效、网络问题或短时限流。重新登录、把“请求间隔”调大后再试；仍失败时，复制诊断信息以及日志里“云盘查重失败 / 提交云盘信息失败”的行反馈。单个文件失败不会阻塞其他文件。

**上传时提示 [400] 接口调用失败（提交云盘信息）**

这是提交云盘条目的阶段失败。先确认登录态有效、NAS 能访问 `musicupload.netease.com`，再重试。日志会带文件名、songid、resourceId、host、appver 和是否有 `MUSIC_U`，反馈时一并提供。

**上传时提示 Connection refused / 无法获取上传节点**

检查 NAS 能否解析并访问 `wanproxy.127.net`。网络恢复后重试；LBS 节点全部不可用时会暂停本轮并保留待处理，不会刷屏。仍失败时把诊断信息里的网络错误发出来。

**同步时提示 [405] 操作频繁 / 上传接口被限流**

遇到 405 时等 10～30 分钟让风控冷却，在设置里把“请求间隔”调到 1.5～3 秒，不要连续点“立即同步”。第一次遇到 405 会暂停本轮，当前文件标记为待处理，其余计入“待续”，下一轮自动继续。

**上传时提示“云盘剩余空间不足”**

每轮同步读取一次云盘容量，并在上传前按“总量 − 已用 − 本轮已上传字节”判断。空间不足的文件不会申请上传 token，会标记为失败，其他文件继续；清理云盘或扩容后点“重置并重试”。如果接口没有返回容量字段，程序保持“容量未知”，不会用 0 误判已满。

**云盘数量没有增加 / 日志显示上传成功但云盘里没有**

先区分上传和补建：`linked` 表示文件字节已经在网易云对象存储，程序只补建云盘条目，不会新增字节。看统计里的“上传”和“补建”是否分开计数。如果云盘数量仍不增加，复制诊断信息和日志里的“补建云盘条目成功 / 云盘已有相同内容”行反馈。

**日志太大 / 日志重复**

`app.log` 单文件上限 2 MB，保留 2 个备份，总占用最多约 6 MB；日志页会显示当前大小和上限。进程 stdout/stderr 写到 `app.out`，不会和 `app.log` 重复。旧日志里的历史重复行不会自动消失。

**自动同步为什么没有运行**

确认设置里的“自动同步”开关是开的。手动暂停也会暂停自动同步，点“继续”恢复；终止只结束当前一轮，不影响自动同步。应用停止后不会运行，重新启动后恢复。

**忽略 / 排除的文件为什么消失了**

命中小文件、扩展名过滤或 `exclude` / `exclude_dirs` 的记录会标记为 `ignored`，不计入总数，也不出现在失败、无权限和待处理列表；这不会删除磁盘文件。取消排除后重新同步会恢复正常处理。

## 二、Docker（可选）

仅在你不想用原生应用，或不在 fnOS 上时使用。Docker 方式与原生应用共用同步核心和状态格式。

### 1. 准备

```text
ncm-cloud-sync/
├── config.yaml
├── data/
└── docker-compose.yml
```

```bash
cp config.example.yaml config.yaml
```

至少设置：

```yaml
music_dirs:
  - /music
data_dir: /data
```

`docker-compose.yml` 默认把宿主音乐目录挂到容器 `/music`（只读），把 `./data` 挂到 `/data`。

### 2. 构建与登录

```bash
docker compose build
docker compose run --rm ncm-cloud-sync login --qr-png /data/qr.png
```

二维码会打印在终端并保存到 `data/qr.png`。扫码确认后会话写入 `data/session.json`。

也可以：

```bash
docker compose run --rm ncm-cloud-sync login --cookie "MUSIC_U=...; __csrf=..."
```

### 3. 试跑与常驻

```bash
docker compose run --rm ncm-cloud-sync sync --limit 5
docker compose run --rm ncm-cloud-sync sync
docker compose up -d
docker compose logs -f --tail=100
```

### 4. 权限

容器默认以 UID/GID 1000 运行。用 `id` 查看音乐目录属主，必要时在 `docker-compose.yml` 的 `build.args` 里改 `PUID` / `PGID`，并确保 `./data` 对该 UID 可写。

### 5. 数据

Docker 数据在宿主 `./data`：`state.db`、`session.json`、`last_run.json`、`qr.png`。备份这些文件即可。

## 三、安全建议

- Web UI 只对管理员开放，但仍不要把 NAS 管理端口直接暴露到公网；
- `session.json` 等同账号登录凭证，备份和分享时注意脱敏；
- 只同步你有权上传的音乐；
- 网易云上传是非公开接口，避免高频、大批量操作；
- 定期备份 `state.db` 和 `session.json`，接口或程序升级后可以快速恢复。
